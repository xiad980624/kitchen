# 小家厨房：产品与交互方案 v0.1

> **当前实现决定（2026-10）**：小家厨房现在是单设备、本地保存的 App。没有账号、邀请、家庭共享、CloudKit 或自建服务器同步；数据不会自动上传。本文中涉及成员协作、邀请和云端同步的内容是早期设想，不是当前实现范围。当前可用的换机保障是“我的 → 本地备份”手动导出和恢复。

## 1. 产品定位

**小家厨房**是一款面向同住家庭的点菜、备餐与冰箱协作 App。它解决的不是“找菜谱”，而是每天共同决定吃什么、家里有没有食材、谁负责买和谁做的问题。

核心闭环：**点菜 → 确认当天菜单 → 核对冰箱 → 采购 → 做饭 → 评价沉淀**。

“家庭”是 App 内的协作小组，不依赖 Apple 系统的家庭共享。用户可创建家庭，并通过邀请链接或邀请码让成员加入。

## 2. 术语

| 名称 | 含义 |
| --- | --- |
| 家庭 | 一组共享菜谱、日历、冰箱与待购清单的成员。 |
| 菜谱 | 一道可复用的菜；包含主菜、辅材、调味料和步骤。 |
| 点菜 | 某位成员表达“想吃这道菜”的意愿，可指定日期或仅加入想吃清单。 |
| 当天菜单 | 某一天已确认要做的一组菜谱。 |
| 冰箱食材 | 家庭当前手动维护的库存。 |
| 待购清单 | 已确认菜单中不足的食材汇总。 |

## 3. 首版用户与权限

- 家庭创建者默认为管理员，可邀请、移除成员与管理家庭资料。
- 所有成员都能新建菜谱、编辑菜谱、点菜、安排日历和维护冰箱。
- 每位成员只能编辑或删除自己的评分与点评。
- 每次菜谱修改都写入修改记录，记录操作者、时间、变更摘要与版本快照；首版只读历史，第二阶段支持恢复旧版本。

## 4. 首版信息架构

底部固定四个入口，顺序与日常使用频率一致：

1. **冰箱**：库存、分类、临期/不足提示、待购清单。
2. **菜单**：今日点菜、想吃清单、常点菜与全部菜谱。
3. **日历**：按日安排菜谱、查看菜单状态与缩略图。
4. **我的**：个人资料、家庭、邀请、成员和设置。

### 菜单页（默认进入）

- 顶部显示家庭名、成员头像与新增菜谱入口。
- “今天吃什么”是首屏重点：展示今日已安排菜谱、家庭成员的点菜意愿及确认按钮。
- 快捷分段：`今天`、`我想吃`、`家庭常点`、`全部菜谱`。
- 搜索支持菜名、食材、分类；筛选支持分类、评分、可做状态和烹饪时长。
- 菜谱卡展示统一缩略图、名称、分类、平均星级、时长、冰箱匹配状态及点菜人数。

### 菜谱详情与新建

菜谱采用四段式卡片，减少传统长表单的压迫感：

1. 主菜
2. 辅材
3. 调味料
4. 操作步骤

详情页顶部先显示封面、评分和冰箱匹配。缺少的食材以橙红色清单单独呈现，并可加入待购清单。页尾提供家庭点评与修改记录。

### 日历页

- 月视图的每一天最多显示三张菜品缩略图；更多菜用 `+N` 表示。
- 用四种状态让安排可一眼判断：想吃、待确认、已安排、已完成。
- 点击某天进入“当天菜单”，可添加、删除、拖动排序或替换菜谱。
- 只有“已安排”的菜谱会参与待购清单计算，避免愿望菜造成误购。

### 冰箱页

- 食材按蔬菜、肉蛋奶、主食、调味料和其他分类。
- 每个食材可输入名称、数量、单位、类别及可选到期日。
- 菜谱匹配按食材显示四种结果：`充足`、`不足`、`缺少`、`待确认`。
- 数量和单位无法可靠换算时，显示待确认而不是错误地判定缺货。

## 5. 关键交互规则

| 场景 | 规则 |
| --- | --- |
| 成员点菜 | 可点给今天或未来日期；同一道菜的多人点菜在家庭视图合并显示。 |
| 确认菜单 | 家庭成员都可以确认；界面明确显示最后确认人和时间。 |
| 编辑菜谱 | 保存时生成新版本与可读摘要，例如“林可将鸡腿肉改为鸡胸肉”。 |
| 食材匹配 | 用标准食材名匹配；首版提供同义词手动合并，复杂换算留给第二阶段。 |
| 评分 | 每人每菜一份可修改评分和点评；列表显示家庭平均分与评价人数。 |
| 删除安排 | 从日历移除后，将对应缺少食材从待购清单重新计算；不会删除菜谱或库存。 |

## 6. 视觉方向：温暖卡通厨房手帐

设计目标是“有食欲、有家庭感、仍然像一个清爽的 Apple App”，避免过度拟物或幼儿化。

### 颜色与排版

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#FFF8ED` | 柔和奶油白，降低信息密度。 |
| 主操作 | `#5F9B7A` | 鼠尾草绿，用于确认、充足状态与主按钮。 |
| 提示 | `#F7A54A` | 胡萝卜橙，用于不足与待确认。 |
| 风险 | `#F06B54` | 番茄红，用于缺少、删除与临期。 |
| 主要文字 | `#37332D` | 温暖深灰，避免纯黑的硬感。 |

- 使用 SF Pro 与动态字号，标题较圆润、正文保持高可读性。
- 采用 8pt 间距系统：页面边距 20pt，卡片圆角 20pt，小标签圆角 12pt。
- 菜谱使用 1:1 统一缩略图。用户没有上传照片时，显示相应菜品的扁平卡通插画。
- 图标以 SF Symbols 为基础，搭配少量食材插画；不用复杂的装饰性图标。
- 动效仅用于确认、加入清单和完成状态，时长控制在 200–300ms。

## 7. 第一版界面清单

1. 欢迎页：创建家庭或通过邀请加入。
2. 菜单首页：今日点菜、家庭点菜动态、菜谱卡列表与搜索。
3. 菜谱详情：四段式内容、库存匹配、评分、修改记录。
4. 新建/编辑菜谱：分步填写、自动保存草稿、保存版本。
5. 冰箱：首页统计、分类列表、添加/编辑食材、待购清单。
6. 日历：月视图、当天菜单、添加菜谱与排序。
7. 我的：家庭信息、成员、邀请入口与个人设置。

## 8. 开发技术方向

- 客户端：SwiftUI；状态管理按功能拆分为菜单、日历、冰箱和家庭模块。
- 数据：CloudKit 作为家庭共享数据源，设备端维护本地离线缓存。
- 身份：优先使用 iCloud 身份做同步；如未来需要跨平台，再增加 Sign in with Apple。
- 同步：菜谱、日历与冰箱数据使用乐观更新；冲突时保留版本记录并提示用户确认。
- 隐私：家庭数据默认仅对受邀成员可见；邀请链接支持失效与重新生成。

## 9. 里程碑

| 阶段 | 产出 | 完成标准 |
| --- | --- | --- |
| 设计基线 | 可点击低保真原型、视觉规范、信息架构 | 确认四个底部页面与核心闭环。 |
| MVP | 家庭、菜谱、点评、日历、冰箱与待购清单 | 两位成员可协作完成一次点菜到备餐流程。 |
| 同步完善 | CloudKit 共享、离线与修改记录 | 跨设备操作稳定、冲突可追溯。 |
| 第二阶段 | OCR、临期提醒、推荐、小组件 | 在真实使用反馈后再逐项加入。 |
